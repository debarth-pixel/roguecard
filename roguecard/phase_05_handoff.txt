Save reliability, stability, and soft-lock prevention.

Audit findings
- The game needed explicit save serialization boundaries, recovery from invalid save files, and safe write behavior.
- A broken or stale save could not be allowed to strand the game in boot or resume an invalid state.
- Settings parsing and runtime recovery also needed stronger type tolerance.

Player-facing changes shipped
- Added versioned run-save serialization through StateManager.build_save_data() and StateManager.restore_save_data(save_data).
- Auto-save now writes active map/combat progress using atomic temp-write-and-replace behavior.
- Resume flow now restores valid in-progress runs and safely discards invalid, corrupt, or terminal save files.
- Invalid save/settings data now falls back cleanly instead of leaving the player in a broken startup state.

Stage 07: Title Screen + Run Modifiers
Status: complete

Objective
- Add a real title/start flow with New Run, Continue, Settings, and Quit.
- Add a data-driven run-modifier system with a 1-of-3 starter draft and event-granted blessings/curses.
- Persist active modifiers and pending draft state safely through save/load.

Short Audit
- The game previously booted directly into a run and had no front-door flow for continue/new-run decisions.
- Runs had no persistent identity layer beyond cards, rewards, and events.
- Event, shop, reward, and combat systems were mature enough to support modifier hooks without a large content rewrite.

What Shipped
- Launch now opens on a title screen instead of auto-starting a run.
- Continue is enabled only when a valid resumable v5/v6 run exists.
- New Run now enters a modifier draft before the map.
- Added 20 data-driven run modifiers in `data/run_modifiers.json`.
- Added modifier loader/validation and a shared modifier engine.
- Added modifier hooks for:
  - on acquire
  - combat start
  - turn one
  - post victory
  - reward generation
  - shop pricing
  - event value
- Added 4 modifier-grant events so blessings/curses can occur from random events.
- Added in-run visibility through a top-bar modifier chip and `I` overlay.
- Save format upgraded to v6 with backward-compatible v5 restore.

Known Remaining Issues
- The current modifier overlay is intentionally compact and can get visually dense if many event modifiers stack up in one run.
- The headless visual capture harness now handles the modifier draft, but it still does not synthesize the GameLoop-owned title screen.
- The run economy has not yet been re-audited with starter modifiers as a major balancing dimension.
